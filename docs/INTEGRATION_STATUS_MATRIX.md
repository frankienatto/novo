# Matriz de Status das Integrações — Synapse Hospitality

| Integração | Status | Descrição Técnica | Requisitos para Produção |
| :--- | :--- | :--- | :--- |
| **Gemini AI** | **CONFIGURABLE** | Provider server-side com runtime tenant-scoped e adapter determinístico de testes. Produção falha fechada sem `GEMINI_API_KEY`; não retorna resposta demo como resultado operacional. | Definir `GEMINI_API_KEY` no ambiente. |
| **Firebase Auth** | **REAL** | Backend implementa validação estrita de tokens JWT no `authMiddleware.ts` via `firebase-admin`. Frontend utiliza Firebase Web SDK com listeners de estado de autenticação. | Configurar credenciais do Firebase no `firebase-applet-config.json` ou variáveis de ambiente de produção. |
| **Firestore** | **REAL** | `firebase-admin/firestore` integrado nativamente com isolamento multi-tenant (`organizationId`/`propertyId`), coleções particionadas e mock in-memory isolado para suítes de testes determinísticas. | Garantir conexão com o Firestore Database configurado no projeto GCP e regras de segurança `firestore.rules` implantadas. |
| **Aloha PMS** | **CONFIGURABLE** | Webhook autenticado e tenant-scoped; eventos exigem identidade externa e unidade canônica. Não é prova de pagamento. | Configurar segredo de webhook e credenciais externas válidas. |
| **Beds24 (OTA/CM)** | **NOT CONFIGURED** | Credenciais não são aceitas no frontend. A integração só poderá ser habilitada por um backend server-side autenticado. | Provisionar integração server-side; nunca usar `VITE_*` para segredo. |
| **Stripe Payments** | **CONFIGURABLE** | Reservation canônica, PaymentIntent server-side, capability pública, webhook assinado e idempotência implementados. | Inserir `STRIPE_SECRET_KEY`, `STRIPE_WEBHOOK_SECRET` e chave publicável para o frontend. |
| **iCal OTA** | **CONFIGURABLE** | Feeds persistentes por unidade, download server-side com timeout/limite, lock, idempotência, conflitos e export sem PII. O proxy legado de URL foi retirado. | Provisionar feeds reais e executar validação no Firestore Emulator/CI antes do release. |
| **Google Calendar** | **CONFIGURABLE** | Rotas autenticadas, tenant-scoped e RBAC para sync/status. Não há OAuth real ou persistência operacional de calendário nesta versão. | Provisionar OAuth server-side e credenciais externas. |
| **n8n** | **CONFIGURABLE (single-tenant por deployment)** | Webhook autenticado por secret e tenant confiável de environment; body não substitui tenant. | Configurar segredo, tenant de deployment e, se necessário, arquitetura de instalações multi-tenant. |
| **Google Ads** | **NOT CONFIG** | Variáveis estruturadas no `.env.example`. Ações de campanhas atualmente operam em modo consultivo/planejamento interno sem disparos diretos via Google Ads API. | Integrar Google Ads Developer Token e fluxo de autorização OAuth2. |
| **Meta Ads** | **NOT CONFIG** | Variáveis estruturadas no `.env.example`. Módulo de marketing opera em modo READ-ONLY estratégico gerando insights sem disparar mutações no Graph API. | Configurar App de Desenvolvedor no Meta for Developers e gerar `META_ADS_ACCESS_TOKEN`. |
